Voxel downsampling with an octree

How downsample() bins points into voxels with integer floor division and averages each cell in one vectorised pass.

What was built

The agent added voxel_downsample() to pointtools. It takes a point cloud and a voxel size and returns one point per occupied voxel — the mean of all points that fall in it. A 12 M point sweep at 0.5 m comes out at roughly 400 k points.

The problem it solves

Dense sweeps oversample flat surfaces and undersample edges. Downstream steps — ground filtering, meshing, the segmentation model — get slower with every point but not more accurate. Downsampling to a fixed spatial resolution keeps the shape and drops the redundancy, so the cost of later steps depends on the area covered, not on how slowly the scanner moved.

How it works

Think of space as a grid of cubes with edge length s. A point at x belongs to cube ⌊x / s⌋ on each axis. That integer triple is the voxel key: two points share a cube exactly when they share a key. So the "octree" is never built as a tree — grouping by key does the same job in one pass.

np.unique(keys, axis=0, return_inverse=True) gives every point the index of its voxel. np.add.at then accumulates coordinates into those slots without a Python loop — plain fancy-index assignment would keep only the last point per voxel. Dividing by the counts gives the means.

How it fits in the codebase

The CLI's thin command reads a LAS file with read_xyz, calls voxel_downsample, and writes the result back. Attributes such as intensity and classification are dropped for now.

Things to watch

  • Memory. The key array is three int64 values per point, so a 50 M point cloud needs about 1.2 GB on top of the input.
  • Large coordinates. National-grid coordinates divided by a small voxel size still fit in int64, but subtract the cloud's minimum first if you ever switch to int32 keys.
  • Means move points. A voxel's mean is not one of the original points; use the nearest point instead if you need exact survey positions.
